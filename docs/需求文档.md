# 项目文档管理网站需求文档

## 1. 项目概述

## 1.1 项目背景
随着企业数字化转型的推进，文档管理已成为日常工作中的核心需求。传统文档管理工具往往功能复杂、操作繁琐，且缺乏灵活的文档预览和筛选功能。本项目旨在开发一款轻量级、易用的在线文档管理网站，帮助用户快速上传、预览和管理DOCX文档。

## 1.2 项目目标
- 提供直观便捷的DOCX文档在线预览功能
- 支持基于标题结构的智能目录生成和筛选
- 实现文档内容的动态显示/隐藏控制
- 保持原文档的高保真渲染效果
- 支持筛选后文档的DOCX和PDF导出

## 1.3 核心价值
- **提升效率**：一键上传，即可预览和筛选，告别传统文档阅读困扰
- **智能管理**：自动识别文档结构，生成可交互的目录树
- **灵活控制**：自由勾选所需章节，定制专属文档视图
- **高保真度**：完整保持原文档的排版、图片、表格等所有元素
- **轻量部署**：无需复杂安装，打开浏览器即可使用

## 1.4 用户群体
- 企业HR：管理员工手册、政策文件
- 产品经理：整理需求文档、产品说明
- 法务人员：处理法律条文、合同模板
- 学术研究者：管理论文、报告、文献
- 任何需要阅读和管理DOCX文档的用户

## 2. 功能需求详述

### 2.1 用户认证功能

#### 2.1.1 注册功能
- **注册方式**：邮箱 + 密码注册
- **邮箱验证**：注册后需验证邮箱（可选）
- **密码要求**：至少8位，包含字母和数字
- **注册反馈**：
  - 注册成功提示
  - 注册失败提示（邮箱已存在、密码不符合要求等）
  - 自动登录或引导用户登录

#### 2.1.2 登录功能
- **登录方式**：邮箱 + 密码
- **记住登录状态**：支持7天免登录
- **登录反馈**：
  - 登录成功进入主页
  - 登录失败提示（密码错误、账户不存在等）
  - 忘记密码功能（可选）

#### 2.1.3 用户状态管理
- **登录状态**：实时显示用户登录状态
- **用户信息**：显示用户邮箱/用户名
- **退出登录**：支持安全退出
- **权限控制**：未登录用户无法上传文档

#### 2.1.4 安全要求
- **密码加密**：Supabase自动加密存储
- **会话管理**：安全的JWT令牌
- **数据隔离**：RLS确保用户只能访问自己的文档
- **退出清理**：退出登录清除本地状态

### 2.2 文档上传功能

#### 2.2.1 基本要求
- **支持格式**：仅支持DOCX格式文档
- **文件大小限制**：最大50MB
- **上传方式**：点击上传按钮选择文件，或拖拽文件到上传区域
- **权限控制**：仅登录用户可上传

#### 2.2.2 文件验证
- 文件类型校验：非DOCX格式提示错误信息
- 文件大小校验：超过50MB禁止上传并提示
- 文件完整性校验：损坏的DOCX文件拒绝处理
- 空文件校验：空白文档提示重新选择

#### 2.2.3 上传反馈
- 进度条显示：显示文件上传百分比
- 状态提示：
  - "正在上传..."
  - "解析文档中..."
  - "生成目录结构..."
  - "预览就绪"
- 错误提示：
  - "文件格式不支持，请选择DOCX文件"
  - "文件大小超过50MB限制"
  - "文件解析失败，请检查文件是否损坏"
  - "请先登录后再上传文档"

### 2.4 目录树展示功能

#### 2.4.1 标题识别
- **自动识别**：扫描DOCX文档，识别所有标题（H1-H6）
- **层级结构**：保持原文档的标题层级关系
- **标题内容**：完整显示标题文字内容
- **特殊字符处理**：正确处理中文、英文、数字、特殊符号

#### 2.4.2 目录树构建
- **树形结构**：以缩进形式展现多级标题
- **层级标识**：
  - H1：不缩进，显示为"1. 标题内容"
  - H2：缩进2字符，显示为"1.1 标题内容"
  - H3：缩进4字符，显示为"1.1.1 标题内容"
  - H4-H6：依次递增缩进量
- **展开/折叠**：支持点击展开或折叠子标题
- **空白标题处理**：自动过滤无文字的标题项

#### 2.4.3 目录项显示
- **复选框**：
  - 生成时默认全部勾选（启用状态）
  - 用户可自由勾选/取消勾选
  - 选中状态视觉反馈：✓已勾选，□未勾选
- **标题编号**：显示当前标题的序号（1、2、3或1.1、1.2等）
- **标题文本**：完整显示标题文字，超长时省略并显示tooltip
- **层级标识**：通过缩进和图标表示层级关系

#### 2.4.4 目录交互
- **单选/多选**：
  - 支持单选某个标题
  - 支持多选多个标题（Ctrl+点击或Shift+点击）
  - 支持全选（全选复选框）
  - 支持反选
- **选择联动**：
  - 取消勾选父级标题时，子级标题自动取消勾选
  - 勾选父级标题时，子级标题保持原状态
- **选择统计**：显示"已选择 X/Y 个章节"（X为已选，Y为总数）

### 2.5 内容预览功能

#### 2.5.1 预览区基本要求
- **单页应用**：所有功能在一个页面内完成
- **左侧目录**：宽度占比20%（1/5）
- **右侧预览**：宽度占比80%（4/5）
- **响应式布局**：窗口缩放时目录区最小宽度200px，预览区自适应

#### 2.5.2 文档渲染要求
- **高保真渲染**：完整保持原文档的排版格式
- **分页保持**：保持原文档的分页结构
- **元素保留**：
  - 文字样式：字体、大小、颜色、粗细、斜体
  - 段落格式：行间距、段落间距、对齐方式
  - 图片：保持原始尺寸和位置
  - 表格：保持表格样式、边框、单元格合并
  - 列表：有序列表、无序列表的编号样式
  - 页眉页脚：必须保持原文档的页眉页脚（注：文档首页默认不显示页眉和页脚，从第二页开始正常显示）
- **超长文档**：支持滚动浏览，提供页面导航

#### 2.5.3 内容筛选显示
- **实时更新**：勾选/取消勾选目录项时，预览区立即响应，显示/隐藏对应标题和内容
- **隐藏逻辑**：
  - 取消勾选某个标题时，该标题及其所有下级内容隐藏
  - 保留其他已勾选标题的内容
  - 隐藏的内容在文档中不占空间（压缩显示）
- **滚动定位**：勾选标题后自动滚动到对应位置

### 2.6 动态序号调整功能

#### 2.6.1 序号重新编号逻辑
- **规则定义**：取消勾选标题后，后续标题序号自动前移
- **示例**：
  - 原始：1. 概述、2. 试用期、3. 工作时间、4. 薪酬
  - 取消"2.试用期"后变为：1. 概述、2. 工作时间、3. 薪酬
- **层级调整**：多级编号同步更新（如1.2.3变为1.1.3）
- **跨层级调整**：处理不同层级间的编号关系

#### 2.6.2 同步更新机制
- **目录区更新**：目录树中的标题编号立即刷新
- **预览区更新**：文档中的标题编号同步修改
- **编号格式**：
  - 纯数字编号：1、2、3...
  - 多级编号：1、1.1、1.1.1...
  - 中文章节：第一章、第二章...
- **样式保持**：编号样式（字体、颜色等）与原标题一致

#### 2.6.3 边界情况处理
- **特殊标题处理**（新增）：
  - **"目录"标题**：不参与序号生成和动态变化逻辑，始终显示原标题。
  - **中文章节**：如"第一章"、"第二章"等，需参与动态重排。
    - **重排规则**：根据当前序号计数器，重新生成中文序号（保持原有的"第 X 章"格式）。
    - **数字转换**：支持阿拉伯数字转中文数字（如 1 -> 一）。
    - **同步显示**：预览区和目录区均需同步更新动态计算后的中文序号。
    - **隐藏逻辑**：取消勾选（作为父节点显示时），目录区和预览区应移除原有静态章节号，仅显示标题文本。
- **首个标题取消**：后续所有标题序号减1
- **中间标题取消**：后续标题序号前移
- **末尾标题取消**：仅影响被取消的标题
- **多级标题**：正确处理各级别的编号重排
- **非连续选择**：只显示选中的标题，序号连续重排

### 2.7 文档导出功能

#### 2.7.1 导出按钮
- **位置**：预览区上方右侧
- **按钮样式**：
  - "导出DOCX"按钮：蓝色主题（MVP版本即有）
  - "导出PDF"按钮：绿色主题（完整版/企业版才有）
- **状态控制**：
  - 无文档时按钮禁用（灰色）
  - 导出过程中按钮禁用，显示加载动画
  - 导出完成后按钮恢复可用

#### 2.7.2 DOCX导出
- **内容筛选**：仅导出用户勾选的标题及其内容
- **格式保持**：
  - 保持原始排版格式
  - 保持标题样式（H1-H6）
  - 保持段落格式
  - 保持图片和表格
- **编号重排**：导出文档中的标题序号与预览区一致
- **文件命名**：
  - 默认命名：原文件名_筛选版.docx
  - 用户可修改文件名
- **兼容性**：导出的DOCX可用Microsoft Word、WPS等打开

#### 2.7.3 PDF导出（可选）
> **注意**：此功能将在项目后期阶段（完整版或企业版）实现，MVP版本暂不包含。

- **内容筛选**：仅导出用户勾选的标题及其内容
- **排版保持**：
  - A4纸张大小
  - 保持原文档的分页
  - 保持图片清晰度
  - 保持表格样式
- **编号重排**：PDF中的标题序号与预览区一致
- **文件命名**：
  - 默认命名：原文件名_筛选版.pdf
  - 用户可修改文件名
- **字体要求**：确保中文字符正确显示

#### 2.7.4 导出反馈
- **进度提示**：
  - "正在生成文档..."
  - "正在压缩文件..."
  - "导出完成"
- **下载方式**：浏览器自动下载到默认下载目录
- **错误处理**：
  - 导出失败提示错误信息
  - 提供重试按钮
  - 支持部分导出（如部分章节导出成功）

## 3. 界面设计要求

### 3.1 整体风格

#### 3.1.1 设计理念（新增认证界面）
- **认证页面设计**：简洁的登录/注册表单，居中卡片式布局
- **视觉一致性**：认证界面与应用整体风格保持一致
- **易用性**：清晰的输入框、按钮和提示信息

#### 3.1.2 用户界面设计要求
- **登录页面**：
  - 邮箱输入框（必填）
  - 密码输入框（必填，隐藏显示）
  - 登录按钮（主要操作）
  - 注册链接（辅助操作）
  - 忘记密码链接（可选）
- **注册页面**：
  - 邮箱输入框（必填）
  - 密码输入框（必填，显示强度）
  - 确认密码输入框（必填）
  - 注册按钮（主要操作）
  - 登录链接（辅助操作）
- **顶部导航栏**（更新）：
  - 未登录：显示"登录"和"注册"按钮
  - 已登录：显示用户邮箱/头像和"退出"按钮

### 3.2 色彩与字体规范

#### 3.2.1 设计理念
- **现代卡片式设计**：采用卡片式布局，每个功能区域独立呈现
- **简约清新**：采用现代化扁平设计，避免冗余装饰
- **易用优先**：减少用户认知负担，操作直观明了
- **视觉层次**：清晰的信息架构，突出核心功能

#### 3.2.2 色彩方案
- **主色调**：蓝色系（#2563eb）
  - 用于主要按钮、链接、强调元素
  - 悬停状态：深蓝（#1d4ed8）
- **辅助色**：绿色（#22c55e）用于成功状态
  - 警告色：橙色（#fbbf24）
  - 错误色：红色（#f5222d）
- **中性色**：
  - 正文文字：深灰（#374151）
  - 标题文字：更深灰（#1f2937）
  - 次要文字：浅灰（#9ca3af）
  - 边框：浅灰（#d1d5db）
- **背景色**：
  - 全局背景：浅灰（#f9fafb）
  - 卡片背景：纯白（#ffffff）
  - 预览区背景：浅灰（#f9fafb）

#### 3.2.3 字体规范
- **中文字体**：苹方、微软雅黑
- **英文字体**：Helvetica、Arial
- **字体层级**：
  - H1：24px，粗体
  - H2：20px，粗体
  - H3：16px，粗体
  - 正文：14px，常规
  - 辅助文字：12px，常规

- **上传**：旋转加载图标 + 进度条

- **位置**：错误字段下方

- **手动关闭**：提供X按钮关闭

## 4. 非功能需求

### 4.1 性能要求

#### 4.1.1 响应时间
- **页面加载**：首页加载时间 < 2秒
- **文件上传**：
  - 10MB文件：< 5秒
  - 50MB文件：< 20秒
- **文档解析**：
  - 10MB文件：< 3秒
  - 50MB文件：< 15秒
- **预览渲染**：
  - 首次渲染：< 3秒
  - 内容筛选响应：< 0.5秒
- **导出时间**：
  - DOCX导出：< 10秒
  - PDF导出：< 15秒

#### 4.1.2 并发性能
- **用户并发**：支持100个用户同时使用
- **文件处理**：支持5个文件同时解析（队列处理）
- **内存占用**：单个50MB文件处理时内存占用 < 1GB

#### 4.1.3 稳定性
- **连续工作时间**：7x24小时稳定运行
- **错误率**：操作成功率 > 99%
- **崩溃恢复**：异常崩溃后自动恢复，用户数据不丢失

### 4.2 兼容性要求

#### 4.2.1 浏览器支持
- **Chrome**：版本 >= 80（推荐）
- **Firefox**：版本 >= 75
- **Safari**：版本 >= 13
- **Edge**：版本 >= 80
- **移动端浏览器**：iOS Safari 13+，Android Chrome 80+

```typescript
class StyleMapper {
  private mapping: StyleMapping;
  private styleElement: HTMLStyleElement;

  constructor(mapping: StyleMapping = DEFAULT_STYLE_MAPPING) {
    this.mapping = mapping;
    this.styleElement = document.createElement('style');
    this.injectStyleSheet();
  }

  // 注入CSS样式到页面
  private injectStyleSheet(): void {
    let cssRules = '';

    Object.entries(this.mapping).forEach(([wordStyle, config]) => {
      const baseSelectors = [
        `.docx-preview [style-name="${wordStyle}"]`,
        `.docx-preview p[style-name="${wordStyle}"]`,
        `.docx-preview div[style-name="${wordStyle}"]`
      ];

      baseSelectors.forEach(selector => {
        cssRules += `${selector} {\n`;
        Object.entries(config).forEach(([prop, value]) => {
          if (prop === 'cssClass') return;
          const cssProp = prop.replace(/[A-Z]/g, '-$&').toLowerCase();
          cssRules += `  ${cssProp}: ${value};\n`;
        });
        cssRules += `}\n\n`;
      });

      // 为CSS类添加样式
      if (config.cssClass) {
        cssRules += `.${config.cssClass} {\n`;
        Object.entries(config).forEach(([prop, value]) => {
          if (prop === 'cssClass') return;
          const cssProp = prop.replace(/[A-Z]/g, '-$&').toLowerCase();
          cssRules += `  ${cssProp}: ${value};\n`;
        });
        cssRules += `}\n\n`;
      }
    });

    this.styleElement.textContent = cssRules;
    document.head.appendChild(this.styleElement);
  }

  // 应用样式映射到DOM元素
  applyStyleMapping(element: Element): void {
    // 方法1：通过style-name属性映射
    const styleName = element.getAttribute('style-name');
    if (styleName && this.mapping[styleName]) {
      const config = this.mapping[styleName];
      element.classList.add(config.cssClass);
    }

    // 方法2：通过层级和内容推断样式
    this.inferAndApplyStyle(element);

    // 方法3：处理特殊场景（列表、表格等）
    this.handleSpecialElements(element);
  }

  // 基于层级和内容推断样式
  private inferAndApplyStyle(element: Element): void {
    if (element.tagName === 'P') {
      // 推断是否为标题（基于字体大小、粗细）
      const fontSize = element.style.fontSize ||
        window.getComputedStyle(element).fontSize;

      if (fontSize && parseInt(fontSize) >= 18) {
        element.classList.add('doc-inferred-heading');
      }
    }
  }

  // 处理特殊元素（列表、表格等）
  private handleSpecialElements(element: Element): void {
    if (element.tagName === 'P') {
      const text = element.textContent?.trim() || '';

      // 检测列表项
      if (this.isListItem(text)) {
        element.classList.add('doc-list-item-detected');
      }

      // 检测引用块
      if (this.isBlockquote(text)) {
        element.classList.add('doc-blockquote');
      }
    }
  }

  private isListItem(text: string): boolean {
    return /^[\s]*([•·▪▫\-–—*]|\d+[\.\)])\s+/.test(text);
  }

  private isBlockquote(text: string): boolean {
    return text.length > 50 && text.includes('"') && text.includes('"');
  }

  // 销毁样式映射器
  destroy(): void {
    if (this.styleElement && this.styleElement.parentNode) {
      this.styleElement.parentNode.removeChild(this.styleElement);
    }
  }
}
```

#### 5.2.4 标题提取实现

**使用mammoth.js + 自定义解析**

```typescript
import mammoth from 'mammoth';

interface HeadingNode {
  id: string;
  level: number;
  text: string;
  index: number; // 在文档中的位置
  visible: boolean;
  selected: boolean;
  children: HeadingNode[];
  number: string; // 动态序号
}

class HeadingExtractor {
  async extractHeadings(file: File): Promise<HeadingNode[]> {
    // 方法1：使用JSZip解析document.xml
    const arrayBuffer = await file.arrayBuffer();
    const zip = await JSZip.loadAsync(arrayBuffer);
    const docXml = await zip.file('word/document.xml').async('string');

    const headings = await this.parseHeadingsFromXml(docXml);
    return this.buildTocTree(headings);
  }

  private async parseHeadingsFromXml(xmlString: string): Promise<HeadingNode[]> {
    const parser = new DOMParser();
    const xmlDoc = parser.parseFromString(xmlString, 'text/xml');

    const headings: HeadingNode[] = [];
    const paragraphs = xmlDoc.getElementsByTagName('w:p');

    for (let i = 0; i < paragraphs.length; i++) {
      const p = paragraphs[i];
      const styleNode = p.getElementsByTagName('w:pStyle')[0];

      if (styleNode) {
        const styleId = styleNode.getAttribute('w:val');

        if (styleId && styleId.match(/Heading(\d)/)) {
          const level = parseInt(styleId.match(/Heading(\d)/)[1]);
          const textNodes = p.getElementsByTagName('w:t');
          const text = Array.from(textNodes).map(t => t.textContent).join('');

          headings.push({
            id: this.generateId(text),
            level,
            text: text.trim(),
            index: i,
            visible: true,
            selected: true,
            children: [],
            number: '' // 将在后续计算
          });
        }
      }
    }

    return headings;
  }

  private buildTocTree(headings: HeadingNode[]): HeadingNode[] {
    const root: HeadingNode = { id: 'root', level: 0, text: '', index: -1, visible: true, selected: true, children: [], number: '' };
    const stack: { level: number; node: HeadingNode }[] = [{ level: 0, node: root }];

    headings.forEach(heading => {
      // 找到合适的父节点
      while (stack.length > 1 && stack[stack.length - 1].level >= heading.level) {
        stack.pop();
      }

      stack[stack.length - 1].node.children.push(heading);
      stack.push({ level: heading.level, node: heading });
    });

    return root.children;
  }

  private generateId(text: string): string {
    return 'heading_' + text.replace(/\s+/g, '_').substring(0, 20) + '_' + Date.now();
  }
}
```

```typescript
    const counters = [0, 0, 0, 0, 0, 0]; // H1-H6计数器

    const traverse = (nodes: HeadingNode[], parentNumber = '') => {

            node.number = counters[0].toString();
          } else {
            counters[node.level - 1]++;
            const numbers = counters.slice(0, node.level).filter(n => n > 0);
            node.number = numbers.join('.');
          }

          visibleIndex++;

          // 递归处理子节点
          if (node.children.length > 0) {
            traverse(node.children, node.number);
          }
        }
      });
    };
```

#### 5.2.8 文档分页优化与经验总结

针对 DOCX 文档在浏览器端预览时分页不准确、内容溢出、页眉页脚缺失等问题，本项目实施了以下增强方案：

1.  **递归式内容拆分 (Recursive Drill-Down)**
    *   **问题**：传统的简单高度截断会导致文字被切半、图片跨页或大段落整体移动造成底部留白。
    *   **解决方案**：实现 `processPage` 和 `splitInside` 函数。当一个元素超出当前页剩余高度时，不再简单地将其移到下一页，而是递归检查其子元素。如果子元素可以拆分，则将前半部分留在当前页，后半部分放入新页。
    *   **核心逻辑**：
        ```typescript
        const splitInside = (element: HTMLElement, remainingHeight: number): HTMLElement | null => {
          // 递归查找可拆分的子节点...
          // 返回拆分后的剩余部分 dom
        }
        ```

2.  **页眉页脚保留 (Header/Footer Preservation)**
    *   **问题**：`docx-preview` 生成的分页通常只在首页或特定节显示页眉页脚，手动分页后新页面丢失页眉页脚。
    *   **解决方案**：在创建新页面时，显式查找原页面的 `<header>` 和 `<footer>` 元素，并使用 `cloneNode(true)` 复制到新页面中。
    *   **布局调整**：计算内容高度限制 (`contentLimit`) 时，需减去页眉和页脚的高度。

3.  **动态页码更新 (Dynamic Page Numbering)**
    *   **问题**：原文档的页码（如 "Page 1 of 10"）在重排后失效或数字不正确。
    *   **解决方案**：在分页全部完成后，遍历所有页面的页脚，查找包含页码的 `<p>` 标签，根据当前页索引和总页数动态更新文本为 `Page X of Y`。

4.  **精确高度调优 (Height Tuning)**
    *   **经验值**：为了匹配 Word A4 纸张的默认分页效果（通常 Word 一页容纳的内容比浏览器默认渲染的 A4 像素高度要少），需要调整 `MAX_HEIGHT`。
    *   **测试结果**：针对标准文档，将 `MAX_HEIGHT` 设定为 **1165px** (包含页眉页脚) 可以达到与 Word (65页) 一致的分页数。

5.  **空白间距优化 (Spacing Optimization)**
    *   **问题**：`docx-preview` 渲染时常在 `article` 或 `section` 开头产生空的 `<p>` 标签，导致页眉与正文之间出现巨大空白。
    *   **解决方案**：在分页前执行 `removeEmptyParagraphs`，移除容器开头的所有空段落。

- **解决方案**：显式设置w:numId="0"禁用自动编号，增强正则处理BOM/NBSP等特殊字符。

## 10. 问题排查与最佳实践

### 10.1 docx-preview 标题映射与序号显示问题

**问题描述**：
在使用 `docx-preview` 渲染文档并尝试将 DOM 元素映射到提取的标题结构时，可能会遇到序号显示异常的问题。具体表现为某些章节标题（特别是文档开头的标题）无法正确显示动态序号。

**原因分析**：
`docx-preview` 在渲染文档时，会将 Word 文档中的"内部目录"（Table of Contents）渲染为普通的段落或文本。这些目录行通常包含章节标题和页码（例如 "第1章. 系统介绍... 4"）。
如果映射逻辑采用顺序匹配（遍历 DOM 查找与标题文本匹配的元素），代码可能会错误地将这些"目录行"识别为章节标题。这会导致：
1.  真正的章节标题数据被目录行"消耗"掉。
2.  当遍历到真正的文档标题 DOM 时，已经没有对应的标题数据可用，导致无法建立映射，进而无法显示序号。

**解决方案**：
在 `mapDomToHeadings` 映射逻辑中，必须增加智能识别和跳过目录行的机制。

**代码参考**：
```typescript
// 检查是否包含 Word TOC 锚点 (高置信度标题)
// 内容标题通常包含这些锚点 (id="_Toc...")，而目录项通常链接到这些锚点
const hasTocAnchor = !!el.querySelector('[id^="_Toc"]') || !!el.querySelector('[name^="_Toc"]');

// 获取该元素的纯文本内容
const text = el.textContent?.trim() || '';

// 检查是否看起来像目录行 (例如 "Chapter 1.... 5" 或 "Chapter 1   5")
// 逻辑: 以数字结尾，且包含制表符、em空格或连续点
// 且不包含 TOC 锚点 (因为真正的标题通常有锚点)
const isTocLine = !hasTocAnchor && (
     // 包含制表符或特殊空格，且以数字结尾
     (/[\t\u2002\u2003]/.test(text) && /\d+$/.test(text)) || 
     // 包含连续点，且以数字结尾
     /\.{4,}\s*\d+$/.test(text)
);

if (isTocLine) {
     console.log(`[DocumentPreview] Skipping TOC line: "${text}"`);
     // 跳过目录行，避免它们"窃取"实际内容的映射
     continue;
}
```

**验证方法**：
1.  使用包含自动生成目录的 Word 文档进行测试。
2.  使用 Chrome DevTools 检查 DOM，确保目录行（通常带有 `docx_` 类名）没有被添加 `__headingNode` 属性。
3.  确认真正的标题元素（通常带有 `_Toc` ID）被正确映射并显示了动态序号。


### 10.2 DOCX 文档分页与渲染优化

针对 DOCX 文档在 Web 端预览时的分页与样式问题，采用以下方案进行优化，以确保高保真还原 Word 文档的视觉效果（如页眉页脚、页码、分页符等）。

#### 10.2.1 技术选型与配置
使用 `docx-preview` 库进行渲染，并开启实验性功能以支持更复杂的布局：
- **Experimental Mode**: `experimental: true`，启用高级布局引擎。
- **Wrapper**: `inWrapper: true`，为每页添加独立的容器。
- **Break Pages**: `breakPages: true`，识别文档中的分页符。
- **Base64 URL**: `useBase64URL: true`，确保图片等资源稳定显示。

#### 10.2.2 手动递归分页逻辑 (Recursive Pagination)
由于默认渲染可能无法精确处理所有内容溢出情况（特别是长表格或连续文本），实现了手动递归分页算法：
1. **检测溢出**：遍历页面子元素，计算累积高度是否超过 A4 纸标准高度（微调为 `1000px` 以匹配 65 页效果）。
2. **元素拆分 (`splitInside`)**：
   - 如果某个子元素（如 `article` 或 `section`）跨页，算法会深入其子节点。
   - 递归计算内部子元素高度，找到精确的分割点。
   - 将超出部分移动到新创建的页面中。
3. **空段落处理 (`removeEmptyParagraphs`)**：
   - 自动移除页眉/标题后的无效空段落，消除不必要的垂直间距，优化版面利用率。

#### 10.2.3 样式隔离与优化
- **页面样式**：为 `.docx` 类添加白色背景和阴影，模拟真实纸张效果。
- **容器背景**：预览区背景设为灰色 (`#f0f2f5`)，突出文档主体。
- **独立性**：确保每一页 (`.docx`) 都是独立的 `block` 元素，避免 flex 布局导致的重叠。

### 10.3 复杂排版问题的深度排查与修复（2025-12-22 更新）

在项目开发过程中，针对高保真预览需求，我们解决了一系列复杂的排版和渲染问题。以下是详细的问题记录与解决方案，供后续开发参考。

#### 1. 目录截断与跨页显示异常
*   **问题现象**：文档目录在第一页底部被截断，第二页未显示剩余目录项，或目录内容在筛选模式下意外消失。
*   **原因分析**：
    *   通用分页逻辑仅根据高度截断，未识别目录（TOC）的语义完整性。
    *   目录节点往往包含特殊的制表符或锚点，普通文本筛选逻辑可能将其误判为"非标题内容"而隐藏。
*   **解决方案**：
    *   **强制分页**：在 `processPage` 中增加 `isTocStart` 检测。若在页面中间遇到目录开始节点，强制插入分页符，将整个目录移至新页面顶部。
    *   **属性标记**：在 DOM 映射阶段，识别目录节点并添加 `data-is-toc="true"` 属性。
    *   **可见性保护**：在 `updateVisibilityAndNumbering` 中优先处理 `data-is-toc` 节点，强制设为 `display: ''`，使其不受 checkbox 筛选状态影响。

#### 2. 页眉防遮挡与版式调整
*   **问题现象**：页眉紧贴页面顶部（top: 0），导致正文第一行内容与页眉重叠，或被页眉遮挡。
*   **解决方案**：
    *   **统一页眉位置**：将所有页眉的绝对定位 `top` 值统一调整为 **40px**，增加视觉呼吸感。
    *   **动态内边距计算**：
        ```typescript
        const requiredPadding = 40 (页眉Top) + headerHeight + 10 (安全间距);
        if (pagePaddingTop < requiredPadding) {
            page.style.paddingTop = `${requiredPadding}px`;
        }
        ```
    *   **分页预判**：在计算分页高度限制 (`contentLimit`) 时，同步扣除这部分新增的保留高度，防止单页内容溢出。

#### 3. 首页内容位置偏移
*   **问题现象**：文档加载瞬间布局正常，但渲染完成后，首页（封面）内容突然上移，破坏了原有的垂直居中或留白设计。
*   **原因分析**：为了消除分页产生的顶部空白，通用优化脚本强制将每一页第一个可见元素的 `margin-top` 设为 `0px`。这对首页的特殊布局产生了副作用。
*   **解决方案**：
    *   在样式调整逻辑中引入索引判断：`if (index > 0 && firstVisible) firstVisible.style.marginTop = '0px';`。
    *   **保留首页布局**：对 `index === 0` 的页面，不做任何强制样式重置，完全信任 `docx-preview` 的原始渲染结果。

#### 4. 横线丢失与布局错乱
*   **问题现象**：文档中用于分割的横线（通常由带边框的空段落实现）在预览中消失，且部分章节间距异常缩小。
*   **原因分析**：项目初期引入的 `removeEmptyParagraphs` 函数为了优化排版，过于激进地删除了所有"空"段落 (`<p></p>`)，误伤了用于布局占位或仅含边框样式的装饰性段落。
*   **解决方案**：
    *   **禁用清理逻辑**：彻底移除或注释掉 `removeEmptyParagraphs` 函数调用。
    *   **原则**：在高保真预览场景下，"保留冗余 DOM" 优于 "破坏原始结构"。

#### 5. 标题多余文字（如 "encesPreferences"）
*   **问题现象**：标题文本显示异常，出现重复后缀，例如 "2.1.2 Preferences" 显示为 "2.1.2 encesPreferences"。
*   **原因分析**：
    1.  系统在更新序号时，会先尝试移除旧序号。
    2.  正则匹配使用了 `el.textContent`，它包含了系统动态生成的序号元素（如 `<span class="dynamic-number">2.1.2 </span>`）。
    3.  正则匹配到了这个动态序号，但在执行 `replace` 或删除文本节点操作时，却作用于后续的标题文本节点（因为动态序号节点被跳过或不可编辑）。
    4.  结果从标题 "Preferences" 中删除了 "Prefer"（匹配到的长度），剩下 "ences"。
    5.  最后标题补全逻辑检测到文本不完整，又把完整的 "Preferences" 拼接在后面。
*   **解决方案**：
    *   **精准获取原始文本**：引入 `getOriginalText` 辅助函数，使用 `TreeWalker` 遍历文本节点时，显式通过 `NodeFilter` 排除 `.dynamic-number` 和 `.dynamic-title-text` 类名的元素。
    *   **逻辑修正**：所有正则匹配和文本替换操作仅针对这个"纯净"的原始文本进行。
